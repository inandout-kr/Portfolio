# Patina (파티나) — 오래 써야 생기는 광택처럼, 시간으로만 쌓이는 익명 평판

> AI는 글·리뷰·계정은 공짜로 만들어내도 **흘러간 시간**은 못 만든다.
> 그래서 평판의 재료를 시간으로만 만든다.

파티나(patina)는 구리나 가죽을 오래 쓰면 생기는 광택이다. 새것으로는 살 수 없고, 흉내 낸 광택은 티가 난다. 평판도 그렇게 만든다.

별점 대신 **신뢰 리텐션 커브**를 보여준다. 나를 믿었던 사람 중 1년 뒤, 3년 뒤에도 아직 믿는 비율이다.
평가는 봉인됐다가 무작위 시점에 풀리고, 여러 개가 모여야 섞여서 공개된다. 그래서 누가 썼는지, 언제 썼는지 알 수 없다.

이 폴더는 **프로토콜 코어 MVP**다. TypeScript 라이브러리, 인메모리 저장, 가상 시계 시뮬레이션으로 구성된다.
drand·체인·ZK 같은 외부 의존은 전부 인터페이스로 주입한다. 그래서 키나 네트워크 없이 테스트가 돈다.

```bash
npm ci
npm test          # 60개 테스트 (규칙 1~12 + 공격 6종 + 어댑터)
npm run demo      # 가상 시계로 4.5년 시뮬레이션 (출력은 아래, 시드 고정이라 매번 같다. --json 이면 수치를 JSON 으로)
npm run mutate    # 엔진 규칙을 하나씩 망가뜨려 테스트가 잡는지 확인 (18/18)
```

Node 22 이상이 필요하다. 개발 의존성은 `typescript`와 `@types/node` 두 개뿐이고, 암호는 `node:crypto`만 쓴다.

## 평가 하나의 생애

```
 만남 ─ 두 사람이 서로 서명 → 체인엔 해시+시각만 (관계 나이가 위조 불가능한 숫자가 된다)
  │
 등록 ─ 관계당 1회, 취소 불가. 이 순간엔 공개 시점을 아무도 모른다
  │      └ 다음 drand 라운드 값 → 공개 지연 1주~3개월 확정
 봉인 ─ 공개 라운드로 타임락 암호화. 받는 사람·운영자·누구도 그 전엔 못 연다
  │
 수정 창 ─ 공개 전 48시간. 몇 번이든 수정 가능, 마지막 것만 유효, 수정했는지는 아무도 확인 못 한다
  │
 해제 ─┬─ [경고] 에스크로. 서로 다른 관계 k=3명이 모여야 묶음째 공개 (한 명의 보복은 묻힌다)
       └─ [지지·중립] 대상별 풀 → 숙성된 관계의 평가가 n=4개 모이면 섞어서 묶음 공개
                         └ 6개월 넘게 안 차면 원문은 버리고 집계만
  │
 재확인 ─ 공개 1년·3년 뒤 "아직도 같은 생각?" → 서명하면 무게↑, 안 하면 조용히 소멸
  │       └ 결과도 n개씩 묶어서만 반영
 커브 ─ 3개월 / 1년 / 3년 유지율 + 표본 수
```

## 확정 규칙 → 구현 → 증명

| # | 규칙 | 어디서 | 증명 (테스트) |
|---|---|---|---|
| 1 | 상호 서명으로만 관계 생성, 해시+시각만, 나이 위조 불가 | `engine.createRelationship`, `notary.ts` | 한쪽 서명 거부 · 기록에 공개키 없음 · 날짜를 바꾸면 머클+체인 검증 실패 |
| 2 | 관계당 1회·취소 불가, 지연은 등록 *이후* 비콘으로, 타임락 봉인 | `registerReview`, `tick` 1단계 | 재등록 거부 · 등록 직후 지연 없음 · 1주~3개월 분포 · 라운드 전 해제 불가 |
| 3 | 공개 전 48시간 수정 창, 무제한, 마지막 것만, 확인 불가 | `submitSealed`, `Member.coverEdit` | 창 전 거부 · 마지막 것만 공개 · 응답은 항상 `{ok:true}` |
| 4 | n개 모이면 섞은 묶음, 날짜·순서·대기 개수 없음 | `tick` 4단계, `views.ts` | n-1까지 비공개 · 항목 필드는 stance·text뿐 · 해제 순서와 무관 |
| 5 | 파생 지표도 묶음 단위로만 | `#computeView`, 30일 고정 주기 | 해제돼도 화면 객체가 그대로 · 점수는 달력 주기에만 갱신 |
| 6 | n은 숙성된 관계(등록 시 30일+)의 평가만 셈 | `Slot.eligible` | 새 관계 평가로는 묶음 안 열림 · 29일 관계 불인정 |
| 7 | 1년·3년 재확인, 안 하면 소멸 | `tick` 5·6단계, `reaffirm` | 2/4 → 50%, 1/4 → 25% · 무응답이면 점수 0 · 한 명의 응답은 안 보임 |
| 8 | 별점 대신 리텐션 커브 | `views.renderCurve` | 3개월·1년·3년 라벨, 비율과 n |
| 9 | 가중치 = 보증인 숙성도 × 관계 나이 × 재확인 보너스 | `weights.ts` | 신규 보증은 베테랑의 1% 미만 · 재확인 후 100배+ · 보너스 비 정확히 2·3배 |
| 10 | 단독 경고는 영향 최소, 서로 다른 관계 k명이면 공개 | `tick` 3단계 | 경고 1·2건 화면 = 안 쓴 것 화면 · 3건째 공개, 점수 하락 |
| 11 | 6개월 넘게 안 차면 집계만 | `tick` 4단계 | 6개월 전 없음, 후 집계만, 원문 0 |
| 12 | 토큰 없음·양도 불가, 체인은 머클루트만 | `ChainNotary` | 체인 페이로드 전부 32바이트 · 자산 연산 API 없음 |

## 공격 시나리오 (`test/attacks.test.ts`)

| 공격 | 결과 |
|---|---|
| **지연 시점 고르기**: 원하는 공개 시점이 나올 때까지 다시 굴린다 | 등록 순간엔 지연을 정할 비콘 값이 존재하지 않는다. 재등록·관계 재생성·다른 라운드 봉인 모두 거부. 작성자가 통제하는 걸 다 같게 두고 비콘만 바꾸면 지연이 바뀐다 |
| **n-1 플러딩**: 아는 평가로 묶음을 채워 남은 하나를 특정한다 | 갓 맺은 가짜 관계로는 묶음이 안 열린다. 경고(warn)로 쓴 평가는 묶음에 없어서 "안 쓴 것"과 구별되지 않는다. 친구 평가도 관계당 1회이고 무작위 지연을 거친다 |
| **점수 변화로 내용 추론** | 지지/중립만 다른 두 세계의 화면이 묶음 공개 전까지 매일 똑같다. 경고를 썼는지는 1년이 지나도 흔적이 없다 |
| **협박자의 수정 여부 확인** | 진짜 수정·위장 수정·여러 번 수정이 공개 직전까지 협박자가 볼 수 있는 모든 출력(화면·응답·일정·체인)에서 똑같다 |
| **가짜 계정 대량 생성** | 계정당 주 10개 관계 상한. 10주에 찍은 가짜 100명의 지지 총합은 **0**이다(만난 날 쓴 보증은 무게가 없다). 묶음도 한 번 못 연다 |
| **한 명의 보복성 경고** | 반복·머릿수 늘리기 불가. 막 관계를 맺은 바람잡이 3명은 공개는 되지만 점수 타격 1% 미만 |

읽는 법:
- **처음 1년은 모두 0 근처다.** 이게 버그가 아니라 설계다. 시간이 재료라서 돈이나 AI로 앞당길 수 없다.
- **지은과 민수는 2년 동안 거의 구별되지 않는다.** 24개월 점수가 6.69 대 6.47이고, 1년 유지율도 92% 대 76%다. 그런데 3년 유지율에서 82% 대 35%로 갈리고, 4.5년 뒤 점수는 155 대 62가 된다. 별점으로는 안 보이고, 시간이 지나야 보이는 차이다.
- **한탕은 초반 지지 비율이 42%다.** 1년 뒤 17%, 3년 뒤 0%로 떨어지고, 경고 48건이 3명 단위로 16번 공개돼 점수가 음수가 된다.
- **공장은 4.5년 동안 가짜 계정을 유지하고 1년·3년 재확인까지 다 해서 35점이다.** 진짜 관계를 맺은 지은(155)의 1/4이 안 되고 민수(62)보다도 낮다. 그리고 "묶음 0 · 집계만 · 100/100/100"이라는, 사람에게선 나오지 않는 모양이 드러난다.

## 확정 규칙 위에 내린 설계 결정

규칙 문장만으로는 정해지지 않아서 내가 정한 것들이다. 전부 `config.ts`와 `engine.ts`에 있다.

- **관계당 1회 = 방향별 1회.** A→B 평가 1번, B→A 평가 1번이다. 같은 두 사람의 관계는 하나뿐이다(운영자 비밀 HMAC 태그로 중복을 막는다. 공개 해시로 두면 누구나 "A와 B가 아는 사이인지" 조회할 수 있다).
- **숙성 기준은 등록 시점의 관계 나이 30일 이상**(규칙 6). 숙성 안 된 관계의 평가는 n에 안 세지만, 묶음이 열릴 때 함께 실려 나간다.
- **경고는 풀에 들어가지 않는다.** 그래서 n에도, 묶음에도, 집계에도 안 잡힌다. 결과적으로 "경고를 썼다"와 "안 썼다"가 밖에서 구별되지 않는다.
- **가중치 공식**: `숙성도(계정 나이) × standing × 숙성도(보증한 순간의 관계 나이) × 재확인 보너스[1,2,3]`
  - 숙성도는 `min(1, 나이/2년)²`이다. 1개월이면 0.002, 1년이면 0.25, 2년이면 1이다.
  - standing은 `0.2 + 0.8·(1−e^−S)`이고, S는 보증인 자신이 받은 공개된 지지의 무게다.
  - 관계 나이는 **보증한 순간 기준**이다. 만난 날 쓴 보증은 0이고, 1년 뒤 재확인을 견뎌야 무거워진다.
- **공개된 경고의 무게**는 관계 나이를 **지금 기준**으로 잰다. 경고엔 재확인이 없고 피해는 보통 짧은 관계에서 생기기 때문이다. 공증된 시간이라 바람잡이도 무게를 얻으려면 수년이 든다.
- **계정당 주 10개 신규 관계 상한.** 가짜 공장이 한 대상에 보증을 쏟아붓는 속도를 시간으로 묶는다.
- **점수(시간에 따라 오르는 값)는 30일 고정 달력 주기에만 갱신한다.** 묶음 공개 같은 공개 사건 때도 갱신한다. 리뷰 해제 시점과 무관하게 해서 차분 공격을 막는다.
- **재확인 응답 기한은 30일**이다. 1년에 소멸한 지지는 3년 지점에서 자동으로 "유지 안 됨"으로 집계된다(코호트 리텐션처럼).
- **집계 폴백은 풀 전체를 한 번에 비운다.** 오래된 1건만 따로 집계하면 그 1건의 stance가 드러나기 때문이다.
- **내용이 깨진 봉인**(서명은 맞음)은 공개 때 "안 쓴 것"으로 처리한다. 봉인은 해제 전엔 검사할 수 없다.

## 알려진 한계 (정직하게)

1. **MVP는 운영자를 신뢰한다.** 투명 멤버십이라 운영자(엔진)는 누가 누구를 평가했는지 안다. 밖으로 나가는 화면에는 드러나지 않지만, 운영자까지 모르게 하려면 v2 ZK(Semaphore)가 필요하다.
2. **n-1 플러딩은 비용만 올린다.** 숙성된 친구 n명이 각자 단 한 번뿐인 자리를 쓰면 남은 하나를 특정할 수 있다. 그래서 비판은 `warn`으로 쓰는 게 안전하다(묶음에 아예 안 들어간다).
3. **집계 폴백은 stance를 흘릴 수 있다.** 공격자가 나머지를 전부 통제하면 "중립 1건"이 누구 것인지 보인다. 원문은 끝까지 안 나온다.
4. **자유 텍스트는 공개 후 지문이 된다.** 협박자가 받아쓰게 한 문장이 묶음에 없으면 수정한 걸 눈치챌 수 있다. 영수증이 없는 건 **공개 전까지**다.
5. **시간을 들인 가짜 계정은 무게가 붙는다.** 그리고 가짜끼리 서로 보증하면 standing도 오른다. 시간이 유일한 재료인 이상, 시간을 쓴 공격은 막을 수 없고 비싸게 만들 뿐이다. 군집 탐지(시드 기반 신뢰 전파)는 v2 과제다.
6. **계정(키) 대여·판매는 막을 수 없다.**
7. **가중치 지문.** 묶음 공개 때 점수 변화량으로 묶음 안 보증인들의 무게 합을 추정할 수 있다. 누가 어느 항목을 썼는지까지는 아니다.
8. **사용자가 적으면 체인 루트 발행 시점 자체가 활동 시점을 드러낸다.**
9. **`MockTimelock`은 tlock의 의미론만 흉내 낸다.** 암호학적 보장은 v2 tlock-js 연동 뒤에 생긴다.

## v2 로드맵

- **drand quicknet 연동**: 비동기 폴러가 캐시를 채우고, `Beacon.randomness`가 캐시를 읽는다. 라운드가 늦게 와도 엔진이 다음 tick에 처리한다(테스트 있음).
- **tlock-js**(`timelockEncrypt`/`timelockDecrypt`)로 `Timelock` 구현.
- **L2 `ChainNotary`**: 하루 한 번 머클루트를 기록한다.
- **Semaphore `MembershipVerifier`**: 운영자도 평가자를 모르게 한다. RLN(Rate-Limiting Nullifier)으로 주간 관계 상한을 익명화한다.
- **경고 임계 암호화**: k명 전에는 운영자도 경고를 못 읽게 한다.
- **군집 탐지**: 시드 기반 신뢰 전파(EigenTrust/SybilRank류).
- **PWA**: `ProfileView`·`ReviewerTask` 계약을 그대로 그린다. 대면 QR 핸드셰이크, 수정 창마다 자동 위장 수정을 넣는다.
