# 묵은지 (Mukeunji) — 익명 평판 프로토콜 (프로젝트 브리프)

이 파일만 읽고 새 세션이 이어서 작업할 수 있게 쓴다. 사용자 요약과 데모 결과는 `README.md`에 있다.
(같은 레포의 루트 `CLAUDE.md`는 별개 프로젝트인 Kairos 브리프다.)

## 현재 상태 (2026-10)
- **MVP 코어 완료**: 확정 규칙 1~12를 엔진으로 구현했다.
- **테스트 60개 통과**: 규칙별, 공격 6종, v2 어댑터 자리.
- **뮤테이션 점검 18/18**: 핵심 규칙을 하나씩 망가뜨리면 전부 테스트가 잡는다.
- **4.5년 시뮬레이션 데모**: 시드 고정이라 출력이 매번 같다.
- **외부 의존은 전부 주입식 목업**이라 키·네트워크가 필요 없다: 시계, drand 비콘, tlock, 체인, ZK 멤버십.
- **다음 작업 = v2**(아래 "남은 일"). 그 전에 사용자와 정할 것: 데모 숫자 기본값(n=4, k=3, 수정 창 48h, 집계 6개월, 숙성 30일, 주 10관계)을 그대로 갈지.

## 명령
```bash
cd mukeunji
npm ci
npm test          # tsc 빌드 후 node:test (spec 리포터)
npm run demo      # dist/demo/simulate.js
npm run mutate    # scripts/mutate.mjs — 엔진을 고치면 반드시 돌릴 것
npm run typecheck
```
Node 22 이상이 필요하다. 개발 의존성은 typescript 5.9.3과 @types/node뿐이다. ESM이고, import 경로는 `.js` 확장자를 쓴다(NodeNext).

## 핵심 철학 (어기면 시스템이 망한다)
- **평가의 재료는 시간뿐이다.** 시각은 주입된 `Clock`과 체인 공증 시각만 믿는다. 주장된 시각(사용자가 보낸 timestamp)은 절대 쓰지 않는다.
- **받는 사람이 못 보는 건 아무도 못 본다.** 대상과 제3자가 보는 화면은 `engine.view(subject)` 하나뿐이다. 이 화면은 공개 사건(묶음·집계·경고·재확인 묶음)이 일어날 때와 30일 고정 주기에만 다시 계산된다. 개별 평가의 도착·해제·수정·재확인이 출력에 흔적을 남기면 버그다.
- **영수증 없음.** 모든 쓰기 응답은 `{ ok: true }` 하나다. 엔진은 마지막 봉인 상자만 들고 있고 이력·횟수는 남기지 않는다.
- **토큰 없음.** 평판을 자산으로 만들지 않는다. 체인에는 32바이트 머클루트만 올린다.

## 확정 규칙 (사용자 확정, 2026-10)
1. 관계는 상호 서명으로만 생긴다. 해시+시각만 저장하고, 관계 나이는 위조 불가다.
2. 평가 등록은 관계당 1회, 취소 불가다. 지연(1주~3개월)은 등록 *이후* 비콘으로 정하고, 내용은 타임락으로 봉인한다.
3. 수정 창은 공개 전 48시간이다. 몇 번이든 수정할 수 있고, 마지막 것만 유효하며, 수정 여부는 확인 불가다.
4. 봉인 풀린 평가가 n=4개 모이면 묶음으로 공개한다. 섞고, 날짜·순서·대기 개수는 보여주지 않는다.
5. 파생 지표(점수·커브)도 묶음 단위로만 갱신한다.
6. n은 숙성된 관계의 평가만 센다.
7. 1년·3년 재확인. 서명하면 가중치가 오르고, 안 하면 소멸한다.
8. 별점 대신 리텐션 커브(3개월/1년/3년 + n)를 보여준다.
9. 가중치 = 보증인 숙성도 × 관계 나이 × 재확인 보너스.
10. 경고 1건은 영향을 최소로 하고, 서로 다른 관계 k=3명이면 공개한다.
11. 6개월 넘게 묶음이 안 차면 집계만 공개한다.
12. 토큰 없음, 양도 불가. 체인은 머클루트 공증용이다.

## 이번에 내린 설계 결정 (규칙 문장만으로 안 정해진 것 — 바꾸려면 사용자와 상의)
- 관계당 1회 = **방향별** 1회다. 쌍당 관계는 하나이고, 운영자 비밀 HMAC 태그로 중복을 막는다.
- 숙성 = **등록 시점** 관계 나이 30일 이상. 미숙성 평가는 n에 안 세지만 묶음에 함께 실려 나간다.
- 경고는 풀에 들어가지 않는다. n·묶음·집계 어디에도 안 잡혀서 "안 쓴 것"과 구별되지 않는다.
- 지지의 관계 나이는 **보증한 순간**(등록·재확인) 기준이다. 만난 날 쓴 보증은 무게 0이다.
- 공개된 경고의 관계 나이는 **지금** 기준이다. 경고엔 재확인이 없고, 피해는 보통 짧은 관계에서 생긴다.
- 계정당 주 10개 신규 관계 상한. 재확인 응답 기한은 30일이다. 1년에 소멸한 지지는 3년 지점에서 자동으로 "유지 안 됨"이 된다.
- 재확인 결과도 n개씩 묶어서 반영한다(상한 6개월). 집계 폴백은 풀 전체를 한 번에 비운다.
- 내용이 깨진 봉인은 "안 쓴 것"으로 친다. 비콘 라운드가 늦게 도착하면 그 슬롯만 다음 tick으로 미룬다.

## 작업 규칙
- `engine.ts`를 고치면 `npm test`와 `npm run mutate`를 둘 다 돌린다. mutate의 원본 조각이 바뀌면 `scripts/mutate.mjs` 목록도 고친다(조각이 정확히 한 번 나와야 한다).
- 새 규칙이나 결정을 추가하면 ① 테스트 ② 뮤테이션 항목 ③ README 표 ④ 이 파일을 같이 갱신한다.
- 화면에 필드를 추가할 때는 "그 값이 개별 평가의 도착·해제·수정 시점에 바뀌는가?"를 먼저 따진다. 바뀌면 묶음 단위로 미뤄야 한다.
- 데모 출력이 바뀌면 README의 데모 블록을 `npm run demo` 결과로 통째 교체한다.

## 알려진 한계
README "알려진 한계"에 9개를 정리해 뒀다. 핵심은 이렇다.
- 운영자 신뢰(투명 멤버십)
- n-1 플러딩은 비용만 올림
- 집계 stance 누출
- 자유 텍스트 지문(영수증 없음은 공개 전까지)
- 시간을 들인 가짜 군집
- 키 대여
- 가중치 지문
- 소규모 시 체인 시점 누출
- MockTimelock은 의미론만 흉내

## 남은 일 (v2)
1. **drand 비콘 어댑터**: 비동기 폴러가 캐시를 채우고 `randomness`는 캐시를 읽는다. 늦은 라운드는 엔진이 이미 처리한다.
2. **tlock-js `Timelock`** 구현. quicknet은 `bls-unchained-g1-rfc9380`이다.
3. **L2 `ChainNotary`**(하루 1회 루트).
4. **Semaphore `MembershipVerifier`**와 RLN 기반 익명 관계 상한. 이게 들어가야 "운영자도 모르는" 익명성이 된다.
5. **경고 임계 암호화**(k명 전엔 운영자도 못 읽게).
6. **군집 탐지**(시드 기반 신뢰 전파).
7. **PWA**: 대면 QR 핸드셰이크, 수정 창 자동 위장 수정, `ProfileView` 렌더.
